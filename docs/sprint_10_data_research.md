# Sprint 10 — 数据源调研与优化

**状态**：待启动  
**目标**：系统性调研各维度数据源的质量、时效性和替代方案，填补当前数据缺口，为 Sprint 11 的数据升级提供依据。

---

## 背景

Sprint 9 在实现各维度数据展示时，发现若干数据源存在时效性、完整性或接口局限问题，需要专项调研后再决策是否替换或补充。本 Sprint 只做调研和结论记录，不做实现。

---

## 调研事项清单

### 1. 北向资金数据严重滞后

**问题**  
`ak.stock_hsgt_individual_em(symbol)` 个股北向持仓数据截止约 2024-08-16，今天（2026-04-25）距今约 20 个月，不具当前参考价值。当前已在 UI 中显示警告，但数据本身无意义。

**调研方向**
- [ ] 调研 AKShare 是否有更新的北向个股持仓接口（如 `stock_hsgt_hold_stock_em`、`stock_hsgt_board_rank_em`）
- [ ] 调研东方财富/同花顺是否有公开的北向个股持仓 API 或页面可直接爬取
- [ ] 评估是否可以用聚合北向板块流向（`stock_hsgt_north_net_flow_in_em`）替代，降级展示为"沪深港通整体净流入"
- [ ] 如实在无个股实时数据，建议 UI 调整：北向资金模块仅对有历史数据（≤3个月滞后）的股票展示，其余显示"暂无实时数据"

**当前临时处理**：滞后 > 365 天时显示黄色警告框，提示用户去东方财富查看。

### 2. 港股南向资金个股数据缺失

**问题**  
A股显示北向资金，港股应对应显示**南向资金**（内地经港股通买入港股）。目前港股直接跳过资金流向模块，等于空白。

**调研方向**
- [ ] 调研 AKShare 南向资金接口：
  - `ak.stock_hsgt_south_net_flow_in_em()` — 整体南向净流入（非个股）
  - `ak.stock_hsgt_hold_stock_em(market="港股通沪", indicator="今日")` — 是否支持单股查询
  - `ak.stock_hsgt_board_rank_em(market="港股通沪", indicator="今日")` — 板块维度
- [ ] 调研东财港股通持仓数据接口（reportapi/个股南向持股比例）
- [ ] 确认港股代码格式（如 `00700`）在 AKShare 南向接口中的参数规范
- [ ] 评估展示方案：若无单股南向数据，是否展示港股板块南向净流向作为参考

**结论待填写**：调研后记录可用接口和参数格式。

### 3. 概念标签（fetch_concepts）性能问题

**问题**  
当前 `fetch_concepts()` 实现策略：遍历东财全量概念板块列表（200+），对每个概念调用 `stock_board_concept_cons_em(symbol=name)` 查询成分股，用 ThreadPoolExecutor 并行，30s 超时。该方案 API 调用量大，速率限制下容易失败。

**调研方向**
- [ ] 调研 AKShare 是否有"个股→所属概念"正向接口（直接返回某只股票的概念标签列表）
  - 候选：`ak.stock_individual_info_em(symbol)` 返回字段中是否包含概念信息
  - 候选：东财个股详情页 API（`push2.eastmoney.com/api/qt/stock/get`）字段解析
- [ ] 调研同花顺个股概念接口
- [ ] 若无正向接口，评估缓存策略：概念板块成分股列表缓存 7 天（概念成分变化慢），减少重复调用
- [ ] 评估展示降级方案：API 失败时，从 `stock_individual_info_em` 的行业字段提取 1-2 个粗粒度标签

**当前状态**：代码已实现（`fetch_concepts()`），待速率限制恢复后 app 中验证。

- [ ] 确认 PE/PB 历史图中 x 轴日期范围和 y 轴缩放是否合理

### 5. 行业对比（Peer）数据覆盖范围

**问题**  
Peer 维度当前用 AKShare 行业分类拉同行，部分行业（尤其港股、细分行业）同行股票数量极少或为空。

**调研方向**
- [ ] 调研行业分类来源：申万行业 vs 东财行业分类，哪个同行覆盖更全
- [ ] 港股 Peer：AKShare 是否支持港股行业分组（`ak.stock_hk_sector_em`）
- [ ] 评估是否增加"用户自定义 Peer 列表"功能（手动指定竞争对手代码）

**问题**

**调研方向**

- [ ] 调研是否可以通过年报关键词抽取（LLM）+ 上市公司公告结构化供应链信息

### 7. 管理层高管背景标签（年报简历解析）

**问题**  
当前管理层模块覆盖 L1（基础档案）、L2（增减持行为）、L3（质押），缺少最有投资洞察价值的 L4（背景标签）和 L5（管理层-战略匹配度）。

高质量管理层分析的核心是：来自哪类公司（华为系/阿里系/外资/国资）→ 执行文化判断；关键岗位背景是否匹配当前战略方向（如 HVDC 子公司 GM 的数据中心经验）。这类信息来自年报"高级管理人员简介"章节，AKShare 无直接接口。

**调研方向**
- [ ] 年报 PDF "第四节 高级管理人员简介" 结构解析可行性（pdfplumber / LLM 抽取）
- [ ] 东财个股详情页是否有结构化高管简历 API 或 HTML 字段
- [ ] `stock_board_member_em` 返回列中是否含"学历/简历"字段（接口版本差异）
- [ ] LLM 知识库辅助标注（对知名高管，LLM 可能已知背景，需控制幻觉风险）
- [ ] 背景标签体系设计：华为系 / 阿里系 / 腾讯系 / 外资高管 / 国资背景 / 学术派 / 创始人

**当前临时处理**：LLM prompt 已引导模型基于公告和行业知识推断背景，准确性有限。
